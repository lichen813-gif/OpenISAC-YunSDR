# Python PHY到C++实时实现约束

版本日期：2026-08-22
适用基线：2×2空间复用、1024/128 CP-OFDM、15.36 Msps、64-QAM。
目标：Python作为算法黄金模型，同时保证接收算法能在Windows/Linux C++ CPU实时实现。

## 1. 基本原则

1. **区分信道仿真与实时接收机。** 逐采样连续Doppler、多径和SFO注入属于测试平台，可以离线运行；真实设备直接提供受损IQ流，C++接收机不需要实时计算信道卷积。
2. **实时算法必须固定复杂度。** 每帧循环次数、矩阵维度和缓存大小均有明确上限，不允许依赖收敛次数不确定的优化器。
3. **优先使用固定尺寸闭式解。** 2×2 MMSE、rank判决和线性拟合在C++中使用展开公式，不调用通用大矩阵求逆/SVD。
4. **流式、预分配、无帧内堆分配。** IQ环形缓冲、FFT输入输出、导频和检测缓存启动时一次分配。
5. **先浮点再考虑定点。** PC/USRP主机版优先`float/complex<float>`和SIMD；只有移植FPGA/低功耗DSP时才单独做定点化。

## 2. 正式实时工作范围

正式C++接收基线配置：

```text
configs/mimo_2x2_spatial_multiplexing_realtime_1024.yaml
```

| 项目 | 基线 |
|---|---:|
| 采样率 | 15.36 Msps |
| 帧长 | 3456 samples / 225 µs |
| 连续满负载帧率 | 4444.44 frame/s |
| 接收天线 | 2 |
| FFT | 1024，固定长度 |
| 数据层 | 2 |
| 实时SFO验证范围 | ±20 ppm |
| SFO补偿 | 8参考音频域线性相位斜率校正 |
| 连续Doppler验收点 | 100 Hz，不做ICI抵消 |
| MMSE维度 | 固定2×2 |

`±20 ppm`来自实际硬件边界。该范围内不再把时域重采样放入实时主链。超过该范围时应先使用硬件时钟校准、低速粗采样率校正或离线`sinc8/sinc24`参考验证。

移动速度必须结合载频换算为Doppler：`fd=v×fc/c`。按2 m/s计算，3.5 GHz约23.3 Hz、5.8 GHz约38.7 Hz、24 GHz约160 Hz；因此100 Hz可覆盖约15 GHz以下的保守边界，而毫米波配置应使用已经扫描过的200 Hz档重新验收。

## 3. 接收模块的C++实现方式

| 模块 | Python黄金模型 | C++实时实现约束 |
|---|---|---|
| ZC定时 | 33个候选位置归一化相关 | 每帧只完整搜索一次；SIMD复相关或滑动相关 |
| 粗CFO | 3个符号CP相关 | 流式复乘累加，1个`atan2`/frame |
| SFO估计 | 8参考点加权直线拟合 | 预计算`k`和`k²`，使用2参数闭式加权最小二乘 |
| SFO补偿 | Symbol 2频域相位斜率校正 | 每个活动子载波1次复旋转；无时域FIR |
| 时域重采样 | Python压力测试可选 | 第一版C++实时主链不实现，不执行第二遍同步/FFT |
| FFT | NumPy FFT | FFTW/MKL/IPP/自带radix-2，固定1024计划复用 |
| CSI估计 | FDM导频LS+线性插值 | 216个导频复除法，分段线性插值；无大矩阵 |
| MMSE检测 | 通用批量线性求解 | 每数据RE展开2×2 Hermitian逆矩阵闭式公式 |
| QAM判决 | 通用标签函数 | 64-QAM分轴阈值比较和查表 |
| CRC | Python逐帧校验 | 256项CRC-16查表或硬件CRC指令 |

工程配置完全取消闭环第二遍：每帧只做一次ZC搜索、一次CP-CFO估计和一组FFT。频域相位斜率校正直接作用于第一遍FFT结果。

## 4. 20 ppm低复杂度选型结果

40 dB、200帧、2×2空间复用、64-QAM实测：

| 方案 | BER | EVM | CRC goodput | 重采样复杂度 |
|---|---:|---:|---:|---:|
| 8参考音，相位斜率校正 | 0.001132 | 0.04067 | 62.658 Mb/s | 0 |
| 8参考音，sinc8闭环重采样 | 0.001116 | 0.03892 | 63.016 Mb/s | 248 Mtap-MAC/s |

无重采样方案保留约99.4%的CRC goodput，EVM增加约4.5%，但直接消除约2.48亿tap-MAC/s、第二次CP-CFO和第二遍FFT。该取舍符合实际`|SFO|<=20 ppm`边界，故固定为工程主链。

连续Doppler与20 ppm组合扫描结果：

| 最大路径Doppler | BER | EVM | CRC goodput |
|---|---:|---:|---:|
| 0 Hz | 0.001132 | 0.04067 | 62.658 Mb/s |
| 50 Hz | 0.001134 | 0.04091 | 62.658 Mb/s |
| 100 Hz | 0.001277 | 0.04238 | 61.584 Mb/s |
| 200 Hz | 0.001948 | 0.04848 | 58.003 Mb/s |

100 Hz仍保留约98.3%的零Doppler goodput，因此第一版不实现ICI抵消。Doppler注入属于Python测试平台，C++接收机只处理其造成的IQ变化。

## 5. 缓存上限

最低接收IQ帧缓存：

```text
2 Rx × (3456 + 32) complex<float> ≈ 55.8 KiB
```

再加单遍FFT网格、CSI和检测缓存，2×2正式配置应把单流水级工作集控制在数百KiB量级，并避免复制完整Monte-Carlo批次。Python的`frames=200`批处理维度只用于统计，不能照搬到C++实时端。

## 6. 后续算法复杂度红线

### 自适应rank/层数

允许：

- 从导频CSI累计一个2×2平均Gram矩阵；
- 用2×2闭式特征值或行列式/迹估计条件；
- 每帧只做一次rank 1/2判决；
- 使用进入/退出双门限和最小保持帧数，避免频繁切换。

禁止：

- 每个数据子载波执行通用SVD来决定rank；
- 穷举预编码矩阵；
- 迭代优化功率分配。

### MCS联动

允许：基于后检测SINR/EVM的固定阈值表选择QPSK/16-QAM/64-QAM/256-QAM，并加入滞回。
禁止：每帧运行机器学习推理、非线性搜索或大规模链路预测。

Python参考现已采用一帧反馈延迟：CRC或质量下降立即降档，升档连续确认3帧并逐级执行。rank和MCS写入下一帧mini-header，热路径只保留平均Gram、闭式特征值、阈值比较和小状态机。40 dB验收比固定Rank-2/64-QAM提高约12.9% goodput；28 dB压力点把CRC失败率从16.7%降至2.1%。

### ICI补偿

第一版只做导频/参考音相位校正，不加入专用ICI抵消。若未来载频与速度使Doppler长期超过200 Hz，先降MCS或rank；仍不足时才评估相邻`k-1/k/k+1`三对角ICI抵消，固定1次迭代。禁止完整1024×1024 ICI矩阵求逆和多次迭代干扰消除。

### LDPC

原OpenISAC C++已经接入自定义LDPC(1008,504)编码器与AFF3CT译码器，默认6次迭代、水平分层NMS；同时提供`float`和可选`int16`定点路径，并已做多线程译码队列。Python现已完成同矩阵编码、软LLR、分层min-sum、扰码、21×48交织、marker/BCH mini-header，以及正式2×2 OFDM混合控制区闭环。工程优化应复用C++现有译码器，并使用`experiments/export_cpp_frame_vectors.py`导出的资源映射、码字、频域网格和时域IQ进行跨语言单元测试。

## 7. C++阶段验收门槛

在确定目标CPU后必须增加以下benchmark，未实测前不宣称“已实时”：

1. 连续IQ输入下平均吞吐不低于15.36 Msps×2Rx；
2. 稳态处理吞吐不低于4444.44 frame/s；
3. 无帧内动态内存分配；
4. 队列不持续增长，无丢帧；
5. Python/C++固定随机向量的同步位置、CFO/SFO、CSI、均衡符号、软LLR、LDPC信息比特和CRC一致；
6. `complex<float>`与Python双精度的BER/EVM差异在预先规定容差内；
7. 分模块记录ZC、FFT、CSI、MMSE、软解调和LDPC的p50/p99耗时。

## 8. 结论

当前算法可以按PC端C++实时方向实现，正式实时子集收敛为：一次ZC搜索、一次CP-CFO、单遍固定1024 FFT、8参考音频域SFO相位斜率校正、线性CSI、2×2闭式MMSE、软解调和复用现有LDPC(1008,504)分层NMS。时域SFO重采样、第二遍FFT和ICI抵消退出第一版主链；连续Doppler信道卷积只属于离线测试负载。
