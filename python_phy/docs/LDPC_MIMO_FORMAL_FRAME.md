# 正式 2x2 MIMO-LDPC 帧结构

## 冻结参数

本帧面向低复杂度 Python 验证以及后续 C++ 实时实现，固定采用：

- 1024 点 FFT、128 点循环前缀、15 kHz 子载波间隔；
- 2x2 空间复用、MMSE 检测、64-QAM；
- 1 个 Zadoff-Chu 前导符号加 2 个数据 OFDM 符号；
- 64/63 个左右保护子载波、直流空置；
- 216 个 FDM 信道导频和 8 个相位参考，共 224 个非数据子载波；
- 672 个数据子载波；
- LDPC(1008,504)，水平分层 Min-Sum，默认最多 6 次迭代；
- CRC-16/CCITT 位于 LDPC 信息区末尾。

一个完整帧时长为 3 x (1024 + 128) / 15.36 MHz = 225 us。

## 两个数据符号的资源映射

第一个数据 OFDM 符号从 672 个数据位置中均匀选取 128 个物理 RE 作为控制区。控制区只由 Tx0 发送单位功率 QPSK，Tx1 静默，接收端使用两天线 MRC。其余资源继续承载双层空间复用。

| 项目 | 数量 |
| --- | ---: |
| 控制区物理 RE | 128 |
| 剩余有效载荷物理 RE | 1216 |
| 双层 QAM 标签容量 | 2432 |
| 每个 LDPC 块所需 64-QAM 标签 | 168 |
| 每帧完整 LDPC 块 | 14 |
| 已编码 64-QAM 标签 | 2352 |
| 填充 64-QAM 标签 | 80 |
| LDPC 信息字节（含 CRC） | 882 |
| 用户载荷字节 | 880 |

控制区包含 64 个固定 Marker QPSK 标签和 64 个 BCH(127,64) 小头部 QPSK 标签。小头部携带版本、调制方式、payload rank、信息区长度、块数和16位帧序号，并带CRC。`flags[3:2]`编码QPSK/16-QAM/64-QAM/256-QAM，`flags[0]`为Rank-2标志；该位为0时表示Rank-1。

## 发送和接收顺序

发送端顺序为：用户字节 -> CRC-16 -> 14 x 504 信息位 -> LDPC 编码 -> 扰码 -> 21 x 48 块交织 -> 64-QAM -> 双层映射。空间复用数据按总发射功率归一化，每层进入天线前乘 1/sqrt(2)。

接收端顺序为：同步 -> 导频信道估计 -> 相位/SFO 斜率校正 -> 控制区 MRC 和 BCH/CRC 检查 -> 双层 MMSE -> Max-Log LLR -> 去交织 -> 软解扰 -> 最多 6 次分层 Min-Sum -> CRC-16。

控制头失败直接把该帧记为 CRC 失败。统计同时保留前 LDPC BER、后 LDPC BER、LDPC 校验矩阵失败率、控制头失败率、CRC 失败率、EVM 和有效吞吐量。

## 工程速率

空中映射总量为 128 x 2 + 2432 x 6 = 14848 bit/frame，对应约 65.99 Mbit/s 的映射速率。880 字节用户载荷对应 31.29 Mbit/s 的最大净载荷速率；实际 goodput 再乘 CRC 成功率。

正式配置位于 `configs/mimo_2x2_spatial_multiplexing_ldpc_realtime_1024.yaml`，验证程序为 `experiments/validate_ldpc_mimo_frame.py`。

## 自适应模式容量

Rank-1使用Tx0单流发送并由2Rx MRC接收；Rank-2继续使用双层MMSE。控制区和导频位置不变，因此控制头可在payload解调前确定rank和MCS。

| ---: | --- | ---: | ---: | ---: |
| 1 | QPSK | 2 | 124 | 4.409 Mb/s |
| 1 | 16-QAM | 4 | 250 | 8.889 Mb/s |
| 1 | 64-QAM | 7 | 439 | 15.609 Mb/s |
| 1 | 256-QAM | 9 | 565 | 20.089 Mb/s |
| 2 | QPSK | 4 | 250 | 8.889 Mb/s |
| 2 | 16-QAM | 9 | 565 | 20.089 Mb/s |
| 2 | 64-QAM | 14 | 880 | 31.289 Mb/s |
